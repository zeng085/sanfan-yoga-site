## 三、差异分析：图册带来什么、缺什么

### 3.1 三大增量（站内完全没有）

**① 铝合金线（21 台）— 最大增量**
站内 `h1` 明写 "Wooden"，**全站无一台铝合金器械**。而图册 AL 系列占 21/69 = 30%，且是**高端商业馆主流选择**（轻、不变形、免维护）。
⚠️ 这一条与现有 `h1` 定位**直接冲突**，是方案必须解决的第一个问题。

**② 折叠线（8 台）— 站内零覆盖的唯一品类**
`Fold 2-Z01` 100kg / `Fold 9-CA` 65kg / `Fold 6 Reformer` 2450×620×**185mm**。
185mm 装箱厚度 = **一个 40HQ 能装数十台**，是跨境小卖家与家用/公寓场景的关键卖点，站内目前**没有任何一句话提到可折叠**。

**③ 包装尺寸 A/B + 毛重（69 台全带）— 站内 100% 缺失**
现有 6 列规格表**没有**任何物流参数。而站内 `container` 一词出现 14 次（说明"测柜量"是已写的卖点），却**没有一行数据支撑**。
B2B 买家第一步就是算柜量 —— 这是本次**性价比最高**的补强。

### 3.2 反向缺口（站内有、图册没有）
- **Spine Corrector（3 台）**、**Studio Set 五件套（3 台）** —— 图册未收录，**保持不动**
- （说明图册不是全集，只能"增量并入"，**不能"整体替换"**）

### 3.3 型号零重叠 → 是两条独立产品线
| | 站内 | 图册 |
|---|---|---|
| 核心床编号 | NIC101 / NIC102 / NLH101… | AL 14-M3 / AL 15-EVO / AL 19-F… |
| 重叠台数 | **0** | |

**结论：不是"同一批货的新图册"，而是两条可并列代理的产品线。** 方案按"扩线"设计，不按"替换"。

## 四、核心冲突与三个决策点

### 决策点 1：`h1` 的"Wooden"怎么处理？（必答）
- `pilates/index.html` 现为 `Wooden Pilates apparatus, built to order`
- 加入铝合金后该 h1 与内容矛盾
- **建议**：改为不锁材质的 `Pilates apparatus, built to order`，副标题写「实木与铝合金双产线 / Solid wood & aluminium, two lines」
- 8 个既有族页 h1 **不动**（它们确实描述实木线，且已上线有排名）

### 决策点 2：主体口径（**需你确认**）
图册主体是 **山东 Comerocky Fitness Technology**，与现有数据源「福建三梵价格表（代理）」是两家不同主体；站内公司主体是福建三梵。
两种口径：
- **A（若 Comerocky 是三梵合作厂/代工方）**：写成 `our partner factory` 或直接并入三梵产品线，工厂背书数据（41000㎡/50+专利/30万台）可作"合作厂实力"引用
- **B（若为另一条代理线）**：按"our partner lines"并列，**不把 Comerocky 的产能数据写成三梵自有**
⚠️ 这条决定全部文案口径，**开工前必须定**。定不下来则先做 P0（纯数据补强，不涉及工厂叙事）。

### 决策点 3：导航怎么加？（有溢出风险）
- 现有 mega menu 已有 8 个 pilates 子项 + "All Pilates apparatus"
- ⚠️ 项目既有铁律：`.container.nav` **不能锁 `--maxw`**，汉堡断点 1279px 是实测标定值（最宽的 es 版需 1436px）→ **平铺再加 2 项有换行/挤压风险**
- **建议（零风险）**：顶层项数不变 —— 把现有 `Pilates Reformer` 改为带子分组的项（实木 / 铝合金 / 折叠），视觉仍占 1 行
- **备选**：导航不动，靠 `pilates/index.html` 新增 2 张卡 + 族页内交叉链接进入（SEO 稍弱但对导航零改动）

## 六、图片方案（**最大不确定项**）

### 6.1 事实核查
- 图册是**纯位图 PDF**：文字层 0 字符，每页 = **1 张整页合成位图**（2398×2433），`get_image_rects()` 显示**无独立产品图对象**，`drawings=0`
- ⇒ **无法像普通图册那样"提取嵌入图"**
- 现有站内 64 张 webp 是**型号级精修图**（白底、统一角度），风格与图册裁切图**不一致**

### 6.2 三条路径（按优先级）
1. **⭐ 首选：向 Comerocky 索取原始产品图**（30 张，白底、与现有 64 张同规格）
   —— 质量最高、风格统一、零返工
2. 退路：从 2398×2433 渲染图**按坐标裁切**（需逐页标定裁切框 ×42 页；背景非纯白、可能带尺寸标注与文字，需逐张清理）
3. 兜底：新 2 页暂用**不配产品图**的版式（表格 + 文字），后续补图

⚠️ 裁切路径的工作量与质量风险都高，**建议先走路径 1**。

## 九、必须遵守的既有纪律（本项目特有）

1. **改 CSS/JS 必须 bump 资源版本号，且与改动同一个 commit**（上一轮因漏 bump 导致线上样式不生效）
2. **改 HTML 标签必须成对**：只改开标签会造成 `<h2>…</h3>` 不匹配，dry-run 与幂等自检都抓不到
3. **新内容不得放进 `<!-- orgref:v1 -->` 标记区间**（该区间会被脚本整段剥离重建，内容静默丢失）
4. **导航目录索引 URL 一律用 `/x/`**，`/x/index.html` 会被 301
5. 落地后必跑：`audit_seo` / `audit_links` / `verify_tag_balance` / `verify_changes_scope` / 168 组合浏览器验收 / 三视口溢出扫描
6. **推送需明确许可**；推送走 REST API 通道，起点判定用「远程 message 匹配 + 逐 blob 树比对 + 两法交叉验证」
