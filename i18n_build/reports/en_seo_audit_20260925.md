## 四、未达标明细与修复方案

### P1 · 直接影响流量与转化

#### P.1 产品详情页正文过薄且模板化

**问题**：115 个产品页（`products/*.html`）词数全挤在 **403–540**，中位 469，低于 B2B 产品页建议的 500–1000 词。对照组：同站 `pilates/*.html` 的 8 个设备产品页是 792–1119 词 —— **同一站点存在两套内容深度**，说明短板来自旧批次模板而非能力不足。

**修复**：按产品逐个补 3 段差异化内容：① 该产品特有工艺/参数取舍（不是通用卖点清单）；② 2–3 个真实应用场景（含使用条件、配套产品）；③ 1 个选型对比段（与站内相邻产品对比，带内链）。参考 `pilates/pilates-reformer.html` 的章节结构复刻到 `products/*.html`。

**预期效果**：147 页产品页是询盘转化的主战场。补到 700+ 词可同时覆盖长尾词并提升页面停留，预期让「产品词 × 应用场景词」这一层级开始有自然流量。

#### P.2 Description 超出 SERP 显示宽度

**问题**：58 页描述超 160 显示宽（2026-09-25 修复前 69 页，最长 217）。超过的部分在 Google 搜索结果里会被截断成「…」，CTA 常常正好被切掉。

**修复**：保留「产品/能力 + 规模或认证 + 询盘动作」三段，删中间修饰语。已按内链权重先修 11 个高权重页，余 58 页同口径推进。

**预期效果**：描述本身不参与排名，但决定点击率。截断修复属低成本高确定性收益。

### P2 · 结构语义与内容质量

#### P.1 H 层级反序（✅ 已修复）

**问题**：曾 158 页出现「首个 h3 先于首个 h2」。2026-09-25 已修：`products/*.html` 规格块 h3→h2（1029 页 / 7 语言）、分类页 cat-head h3→div.cat-title（70）、`faq.html` 分类标题 h3→h2（35）、`blog.html` 卡片 h3→h2（80）、`blog/*.html` 空 href 的 `<a data-setlang>`→`button`（18）。

**修复**：无需再动：`fix_en_seo_structure_20260925.py --check` 应为 0 处。

**预期效果**：层级清晰帮助 Google 抓取页面主次，也利于 AI 摘要抽取段落。

#### P.2 面包屑缺失

**问题**：14 页缺面包屑：10 篇文章 + about/contact/faq/blog 列表页；其中 10 篇文章已有 BreadcrumbList 场景但未实现（对应 Schema 缺项）。

**修复**：给这 14 页加视觉面包屑 + `BreadcrumbList` JSON-LD。首页不加（Google 不接受首页面包屑）。

**预期效果**：面包屑会在 SERP 中以路径形式展示，替代长 URL，提升可信度与点击率。

#### P.3 `<a data-setlang>` 缺 href

**问题**：9 个 blog 文章页的语言切换用了 `<a data-setlang>` 且没有 `href`，而其他 167 页用的是 `<button data-setlang>`。无 href 的 `<a>` 不可聚焦、语义错误，键盘用户无法切换语言。

**修复**：把这 9 页的 `<a data-setlang>` 改成与全站一致的 `<button type="button" data-setlang>`。

**预期效果**：一致性 + 可访问性修复，同时消除一类标记缺陷。

#### P.4 同页多图共用同一 alt

**问题**：143 页的产品画廊把同一产品的 5–9 张图全部写成同一句 alt（如 `AB Roller Training Set` ×9）。

**修复**：按图位拆分：主图=`产品名 + 核心材质/规格`；细节图=`…细节（纹路/厚度/包边）`；场景图=`…在 <场景> 中的使用`；对比图=`…与其他材质对比`。

**预期效果**：让图片搜索能分别命中「细节」「场景」类查询，属增量流量机会。

#### P.5 Title / Description 偏短

**问题**：40 页 Title <45 宽（最短 33），46 页 Description <120 宽（最短 84）——主要集中在小件产品与 about/contact 等页。

**修复**：补入具体价值信息（工厂能力、认证、起订量、打样周期），避免用「OEM」「Supplier」这类泛词凑长度。

**预期效果**：SERP 展示位是免费的，长度用满才不浪费。

#### P.6 产品中心 H1 过于宽泛

**问题**：`products.html` 的 H1 是 「Our Products」，未承载任何关键词。

**修复**：改为承载核心类目与定位，如「Yoga & Fitness Equipment — Full OEM/ODM Product Range」。

**预期效果**：H1 是页面主题最强信号。

## 五、为什么这份结论可信（已排除的误报）

| 疑点 | 排查手段 | 结论 |
|---|---|---|
| 「1140 处 hreflang 指向不存在的页面」 | 审计器初版只加载英文页做目标集合；实际 `de/about.html` 等 1140 个目标文件均存在 | **我的脚本 bug，已修**，修正后该项归零 |
| 「正文词数是否被静态抽取少算」 | Playwright 渲染 `document.body.innerText` 与静态抽取逐页对比 9 页 | 静态**从不低算**（about 370/369、contact 116/111），差值来自 `<details>` 折叠内容与隐藏块——而 Google 索引折叠内容，故静态口径正确 |
| 「词数是否被中英配对块污染」 | 核对 CSS 与标记：`.lang-zh{display:none}`，且 H1 为内联配对 | 需先剥块再抽取；已用**标签配平**剥块（非贪婪会在嵌套 div 处截断） |
| 「图片缺 width/height 算不算 CLS 缺陷」 | 查 `styles.css` | `.prod-card .ph` / `.pd-main img` / `.pc-img` 等已设 `aspect-ratio`，**已有兜底** → 降级为提示，不计不达标 |
| 「9 页 `<a data-setlang>` 无 href 是否误读」 | 全站统计：1140 个语言目录页的同类标签**都带 `href`**，仅这 9 页漏 | 确认为真缺陷 |
| 「Sitemap 是否漏页」 | 交叉 `sitemap.xml` 的 1330 条与 190 个可索引页 | 零漏页 |
