### ⭐ 踩坑：API 推送后 Vercel 没触发部署，怎么救
现象：commit 已到 GitHub（`/commits` 能看到 eb608a3ec），但 `/deployments` 列表最新还是上一版，
线上 curl 到旧 robots.txt，`x-vercel-cache: HIT` 且 age 一直涨 → 判定为 **部署未触发**，不是缓存。
排查三步：
1. `GET /repos/{repo}/deployments?per_page=5` → 最新 SHA 是否等于刚推的
2. `GET /repos/{repo}/commits/{sha}/check-runs` → total=0 也印证 Vercel 没跑
3. `GET /repos/{repo}/deployments?sha={sha}` → count 0 即实锤
**解法（已验证有效）**：用同一棵树创建一个空提交再 PATCH ref，重新产生 push 事件：
```python
parent = GET /git/ref/heads/main -> object.sha
tree   = GET /git/commits/{parent} -> tree.sha
c      = POST /git/commits {"message":"chore: retrigger Vercel deploy","parents":[parent],"tree":tree}
PATCH  /git/refs/heads/main {"sha": c.sha, "force": False}
```
2 分钟后新 deployment 出现，线上全量生效。空提交无害，可反复用。
**教训**：推送后必须查 `/deployments` 确认，不要只看 `/commits`；更不要靠刷 curl 判断"缓存没清"。
