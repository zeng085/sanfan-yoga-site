## 踩坑记录（重要）
1. **占位符必须用纯 ASCII**：非 ASCII 的 `☁TM0☁` 会被翻译引擎改写/吞字符导致泄漏。用 `ZXQTM0QXZ`。
2. **占位符会被插入空格**：日语返回 `ZXQTM 0 QXZ`，精确 replace 失败 → restore 需多档宽松正则 + 残片兜底清理。
3. **PROTECT 正则必须加词边界**：`PU` 会误匹配 "out**pu**t"、`NR` 会误匹配 "Faszie**nr**ollen"。
4. **数值+单位不能加 `\b`**：`㎡` 非 `\w`，`\b㎡\b` 匹配失败 → `12,000㎡` 被误译成 `12.000 €`（面积变欧元）。改用 `\d[\d,.\s]*(?:㎡|m²|sqm)`。
5. **未译率统计口径**：短标签（FAQ/Blog/SANFAN/2013/100 pcs/ISO 9001/邮箱电话/品牌）保留原文是**正确行为**，计入分子会把合格页面误判不合格。只统计长度 ≥20 字符且非专有名词的条目。
6. **续翻脚本绝不能重判已存在页面**：曾误把已上线的合格页面（未译率误报 8.2%）移入 `_pending`，破坏已交付成果。改为「已存在一律 skip，只补缺失页」。
7. **zsh 不做变量自动分词**：`for P in $PAGES` 在 zsh 下当成一个整体，必须用数组 `PAGES=(a b c)`。
8. **长驻进程会被 OOM kill（exit 137）**：翻译/生成多页时必须逐页独立子进程。
9. **MyMemory 对 429 要快速失败**：否则重试 4 次×递增 sleep，整批处理卡死十几分钟。

## 严重故障：Vercel 部署静默卡死（域名切换后所有改动都没上线）

**现象**：线上 `sitemap.xml` 仍用旧域名 `sanfan-yoga-site.vercel.app`、语言页 0 条；
`/de/`、`/ko/index.html` 全部 404。但 git push 都显示成功。

**根因**：`vercel.json` 的 redirect 写成了
```json
{ "source": "https://sanfan-yoga-site.vercel.app/:path*", "destination": "https://fjsanfan.com/:path*" }
```
Vercel 的 `source` **必须是路径模式**，写成完整 URL 会导致构建配置错误 → 部署失败。
该 vercel.json 是域名切换（fe7aa4f）时引入的，也就是说**从那之后的改动一直没上线**
（SEO 修复、静态产品页、hreflang、多语言……全都卡住）。

**正确写法**（跨域名跳转要用 `has` 匹配 host）：
```json
{
  "redirects": [{
    "source": "/:path*",
    "has": [{ "type": "host", "value": "sanfan-yoga-site.vercel.app" }],
    "destination": "https://fjsanfan.com/:path*",
    "permanent": true
  }]
}
```
修复后推送 `3ea92d6`，部署立刻恢复：sitemap 用新域名、`/de/` 200、DE/JA/KO 各 10 页全部 200。

**教训**：git push 成功 ≠ 部署成功。以后做完站点改动，必须 curl 线上 URL 验证实际内容
（尤其检查 sitemap 里的域名/条数是否符合预期），不能只看 push 输出。

2. 我把 **GitHub PAT 硬编码**进 `push.sh`（`PAT=ghp_...`）。

   该提交**未推送成功**（被拦下），所以 PAT 未暴露到远程。

**关键认知**：删除密钥的那个提交，其 **diff 本身就含密钥原文**（`-key` 那一行），
所以"加一个删除提交"不能通过 push protection，必须**重写历史**。

**清理流程（可复用）**：
```bash
# 1) 先移除工作区密钥：改为环境变量或 .gitignore 排除的本地文件
# 2) 重写历史（--index-filter 比 --tree-filter 快很多）
FILTER_BRANCH_SQUELCH_WARNING=1 git filter-branch --force --index-filter \
  'git rm -r --cached --ignore-unmatch <含密钥文件> -q 2>/dev/null || true' \
  --tag-name-filter cat -- --all
# 3) 关键：删除 filter-branch 备份引用，否则 git log --all 仍搜得到
git for-each-ref --format="%(refname)" refs/original/ | while read r; do git update-ref -d "$r"; done
git reflog expire --expire=now --all && git gc --prune=now -q
# 4) 复查
git log --all --oneline -S "<密钥片段>" | wc -l    # 必须为 0
# 5) 强推（--force-with-lease 会因 ref 已重写报 stale info，用 --force）
git push --force origin main
```
**踩坑**：
- `git add -A` 会把 `filter-branch` 的临时目录 `.git-rewrite/` 一起提交（里面含密钥原文），
  清理时要连同 `.git-rewrite` 一起 `git rm --cached`。
- `--force-with-lease` 在 filter-branch 后报 `stale info`，改用 `--force`。

**必须做的事**：
- DeepL key 已进远程历史 → **用户需到 DeepL 控制台轮换**
- GitHub PAT 虽未推送成功，但已被 GitHub 识别 → **建议一并轮换**

## 🔑 重大发现：git 协议被代理阻断时，用 GitHub REST API 推送（可复用）
**现象**：`git push` 连续失败 `CONNECT tunnel failed, response 502` / `Empty reply from server`，重试 5 次全挂。
**排查关键**：分端点测连通性，结果**不一样**：
- `curl https://api.github.com/user`（带 Bearer PAT）→ **200 通**
- `curl https://github.com` → **000 不通**
- `git push`（走 github.com）→ 全挂

**结论**：代理只放行 `api.github.com`，git 的 HTTPS 端点被拦。所以**改用 REST API 四步提交**，完全绕过 git 协议：
1. `GET  /repos/{repo}/git/ref/heads/main` → 拿 base commit sha
2. `GET  /repos/{repo}/git/commits/{sha}` → 拿 base tree sha
3. 每个改动文件 `POST /repos/{repo}/git/blobs`（content 用 base64，encoding="base64"）→ blob sha
4. `POST /repos/{repo}/git/trees`（base_tree + tree 数组）→ 新 tree sha
5. `POST /repos/{repo}/git/commits`（message + tree + parents=[base_commit]）→ 新 commit sha
6. `PATCH /repos/{repo}/git/refs/heads/main`（sha=新 commit）→ 完成

脚本化在 `/tmp/gh_push_api.py`（PAT 从环境变量 `GH_PAT` 读，**绝不写进文件**）。
本次用它推送 commit `d34f7762`（德语 title 修复），Vercel 正常触发部署。

**⚠️ 副作用**：API 提交的 commit **SHA 与本地 git 生成的不同**（同样内容、同样 message，但 committer 信息不同）→ 本地与远程分叉。
处理：本地 `git reset --soft <远程父提交>`，让 HEAD 退到远程 commit 的 parent，工作区改动保留（显示为 staged）。
网络恢复后 `git fetch && git reset --hard origin/main` 即可完全对齐（工作区内容不变，因为远程内容与本地一致）。

**踩坑**：写重试循环时 `if git push | tail -2; then` 判断的是 `tail` 的退出码（恒为 0），会把失败误判成成功。
必须 `git push > log 2>&1` 后直接判断 `git push` 自身退出码。
