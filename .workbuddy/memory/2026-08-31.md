## 全站 SEO 基础元素审计与修复（meta / 双重转义 / 多语言描述）

### 起因

### 严重事故与回滚（重要教训）
- 第一版 `/tmp/escape_meta_quotes.py` 用单个大正则 `(<meta\s+[^>]*?content=(["']))([^"\']*(?:["\']*)+)(\2)`
  批量转义 meta content 值内的裸双引号（英寸符号 `10"`），
  **结果作用域失控**：把属性名引号也转义了（`name="description"` → `name=&quot;description&quot;`），
  288 文件 / 40393 行被破坏。
- 修复：`git checkout -- .` 全量回滚（本地 HEAD=977f341 与 origin/main 对齐，此前修复均已推送，回滚零损失）。
- **正确做法（`/tmp/fix_meta_content_quotes.py`）**：不用大正则，改用**逐字符状态机**——
  先用 `<meta\b[^>]*>` 取标签，再定位 `content=`，只在值区间内把裸 `"` 替换为 `&quot;`。
  最终结果 31 文件 / 106 行，属性名零影响。

### 两个隐蔽 bug（同一个功能的第二、三轮错误）
1. **值内成对引号误判**：`Rullo "EVA" in materiale...`（意大利语成对引号），
   第一版"结束引号后跟空白/>/"的启发式把 `EVA` 后面的引号当成结束引号，只转义了前一个，
   反而让截断更严重。
   修法：升级为 `_is_value_end()` —— 结束引号之后到 `>` 之前，只能剩下
   `空白 + 可选 /`（标签收尾）或 `空白 + 新属性名=`（后面还有属性），否则判定为值内裸引号。
   → 修复量从 169 处提升到 177 处。
2. **注意**：英文站 `products/fi5.html`、`products/ym5.html` 原本就有 `&amp;amp;`（更早流程遗留）。

### 双重 HTML 转义（新发现，比 title 过长严重）

### 审计脚本两个自身 bug（教训）
1. **link 标签属性顺序有 3 种变体**：产品页 `rel=alternate → hreflang → href`（rel 最前）、博客页 `href → hreflang → rel`（href 最前）、其他页 `href → rel → hreflang`。
   用"rel→hreflang→href / href→rel→hreflang"两种顺序正则会漏掉 href 最前的一种 → 误报 150 处缺 hreflang。
   **正确做法**：用 lookahead 宽松匹配 `(?=[^>]*\brel=...)(?=[^>]*\bhreflang=...)(?=[^>]*\bhref=...)` 后分别提取属性。
2. **反引检查语义**：语言页 entries 的 en 和 x-default 条目**都**指向英文页，所以 `refs[英文页]` 天然 = {'en','x-default'}；6 语言是加在语言页自身 URL 上。
   误写成"refs[英文页] 应含 6 语言" → 误报 41 处缺反引。
   正确验证：refs[英文页] 含 'en' + 语言页 x-default 指向英文站（非 /xx/ 路径）。
